# WeChatKit 实施记录（2026-10-21）

## 目标与授权

用户要求新建自包含的微信插件，独立重写 WCPulse / WCRefine / WeX 的指定功能，已明确没有源码。仅改 `/var/minis/workspace/wechat-kit/`；不修改原三个 dylib、微信文件或已安装插件。不从二进制复制机器码、授权代码、账户资料、网络服务或原作者资源。

本轮可做：本地源码、针对性静态定位、测试、iOS 交叉编译以及准备 CI。尚未授权 commit / push / 新建远端仓库 / 云端触发 / 安装 / 重启 / 改设备数据。现有连接、旧会话授权不自动扩大范围。

## 假设与版本

- 首个适配目标为已 dump 的微信 `8.0.69.33`，最低 iOS 15。
- 本地路径名为 iPhoneOS16.5.sdk 的 SDKSettings 实际声明 **16.4**，交叉编译必须报告实际 SDK，不能只信目录名。
- 头文件是元数据还原，不一定可直接编译；微信私有接口必须核 type encoding。
- 原 `FEATURES.md` 中「顶部标签」被写成底栏标题、「群聊标签」被写成会话分组。这两项先核实，不能把推断当用户确认。
- 净化、圆角的「所有功能」以实际 UI 子项与行为为清单，不用整个 plist 中关键词计数代替功能数。

## 方案

1. 新建 Theos 工程，独立命名空间 WCK / com.doimty.wechatkit，无原插件依赖。
2. 主开关与实验开关默认关闭；未实现功能明确禁用，不设置假开关冒充可用。
3. 每一私有 hook 有 bundle + build + class + return/argument type 门控，不匹配则保持原行为；调用原 IMP，不覆盖用户其它插件文件。
4. 设置入口放在微信设置页右上角「WCK」，避免依赖原作者插件中心；不得破坏原右侧按钮。
5. 先做有确切接口的模块。禁止热更新须定位微信真实 patch 加载链，不能仅写猜测 ABTest key、拦所有更新或伪造成功。
6. 清未读只由用户明确长按动作调用，不构造后台自动清消息、不测试性修改真实未读。
7. UI 修改支持关闭与 cell 复用恢复，不全局扫 UIWindow、不全局改所有 UIImage/UILabel/UIView。

## 成功标准

- 工程与测试真实落盘，接口有可复核证据；同版本 ABI 缺失不安装 hook。
- 全部源码通过实际 Apple SDK 的 arm64 / arm64e 语法及对象编译；C 策略测试在本机真实运行，包括坏类型、边界、版本拒绝与变异负例。
- 未实施子项在目录和设置页都标「待实现 / 待定位」，不得声称整体完成。
- 正式 RootHide PAC00 包须获准后在 GitHub Actions 的 Xcode 工具链编译；本机 Linux arm64e 对象不等于真机可用包。

## 独立失败信号与验证

- 非微信/其它微信 build/错 ABI 仍装 hook：失败。
- 关闭开关仍改原行为、继承/复用导致重复手势或丢原按钮：失败。
- 缺原作者 dylib 或网络授权会崩：失败。
- 设置页出现未实现功能的可开关状态：失败。
- 将宿主 C 测试 / 语法检查 / 对象编译写成已链接 deb 或真机成功：失败。
- 验证分层：C 宿主执行；Python 源码合同；iOS SDK cross compile；后续云链接/打包；后续授权真机 A/B。每层分别记录。
